# 架构与设计取舍

## 执行路径

~~~mermaid
flowchart LR
  A["TXT / Markdown"] --> B["输入校验"]
  B --> C{"执行方式"}
  C --> D["Python 规则提取"]
  C --> E["Ollama JSON 输出"]
  D --> F["Pydantic + 原文引用校验"]
  E --> F
  F --> G["等待人工审核"]
  G --> H["审核通过"]
  G --> I["审核退回"]
  H --> J["生成 Markdown"]
  B -.-> K[("SQLite")]
  F -.-> K
  H -.-> K
  I -.-> K
~~~

浏览器演示直接调用 JavaScript 提取规则；本地服务通过同源 API 执行 Python 流程。没有把静态演示伪装成后端或模型执行。

## 任务状态

- queued → running → awaiting_review → succeeded / rejected
- queued / running / awaiting_review → cancelled
- 处理、连接、超时或引用校验失败 → failed
- 服务启动时将残留 queued / running 标记 failed
- failed / rejected / cancelled 可创建关联 parent_id 的新任务

运行配置在提交时冻结。设置页改动只影响之后的新建任务；不会改变运行中任务或已有报告。

## 为什么使用固定流程

第一版先验证资料整理这个具体任务的端到端行为。固定顺序避免将大量时间花在通用图编辑器和复杂调度上。真正的模型步骤只有结构化提取，其余步骤是可检查的程序逻辑和人工审核。

## 持久化与并发

SQLite 存储运行 JSON 与配置。每次状态变更在 BEGIN IMMEDIATE 事务中进行，同时增加 version。
审核事务同时验证状态与版本，写入审核结果和报告；后提交的过期审核不会覆盖先前结果。
连接每次使用后关闭，兼容 Windows 文件锁。

异步任务通过 Semaphore 限制并发。取消既修改持久状态，也取消对应 asyncio Task；等待模型响应时可以中断。
单进程是当前明确约束。多进程部署需要另行引入任务归属、租约与独立工作进程。

## 输出可信度

- 模型输出必须符合类别、文本及正整数行号的契约。
- 文本必须是指定原文行的连续片段，重复引用拒绝通过。
- 原始提取结果与审核后结果分别保留，运行 JSON 可看到修改前后。
- 这只能验证引用出处，不能判定原文事实真伪、是否断章取义或分类是否准确。
- Markdown 中转义源文本特殊字符，网页中对文本进行 HTML 转义。
- Prompt 将源文本声明为不可信资料；它不能替代输出校验和人工审核。

## 模型与测量

Ollama 使用 /api/chat、stream=false、JSON Schema 和 temperature=0。temperature=0 也不代表不同硬件或模型版本间绝对确定性。
只有网络连接与超时进行有限重试；错误 JSON 和引用错误保留为失败，便于诊断。
步骤耗时由单调时钟测量，包含该步骤的持久化开销，不包含人工等待时间。
Token 读取模型返回值，规则模式不报告 Token 或成本。

## 评测设计

`evals/cases.json` 是一组作者标注的诊断回归资料。每条标签要求模型同时满足原文行、引用片段和类别；空内容样本要求拒答。评测脚本会分别记录 schema 通过率、原文引用通过率、精确率、召回率、F1、拒答正确率和延迟，并把失败拆成漏项、错类、额外项、引用不完整和引用失效。评分器不使用第二个模型当裁判，避免把判断标准藏在不可复现的生成结果里。

规则基线故意保留为对照。它能处理显式关键词，却会在隐含语义、否定和语境中暴露边界；后续 Prompt 或模型改动要以同一数据集重新运行，并查看失败案例是否转移，而不是只追求一个汇总数字。

## 本地部署范围

默认监听 127.0.0.1，限制 Host 与 API Origin，不设置宽泛 CORS。
浏览器只访问静态白名单文件，不能读取数据库、环境文件或后端源码。
当前没有用户认证、权限隔离或公网防护；它是本机单用户工具。
